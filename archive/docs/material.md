## 0. 三条主线

面试或写长文，先讲这三条，其他素材都是它们的注脚。

### 主线一：评测先于功能

- 旧评测的期望值是照着一份 Excel 硬算的；数据一换全红，失败原因跟代码无关。
  重写之后，期望值从 fixture 现算，每条用例一个临时库，不碰真实数据。
- 攻击用例的判据不是“返回了 4xx”，而是**三件事同时成立**：被拒绝、数据零变化、
  该保护的还在（canary 文件没被删、审计没多一条）。
- Agent 层必须自己扮演用户点确认，否则删除/导入/改结构一半的工具测不到；
  熔断、超时、压缩用假模型测，因为真模型每次“第几次停”都不一样。
- 数字用现在的：**182 条（离线 142 / Agent 40）**。不要再用 15 / 31 / 141。
- 位置：`decisions.md` 1110–1118；完整故事在 `eval/README.md`。

### 主线二：中断不是异常，是一等状态

- `ask_user` 和确认卡片是同一种机制：工具挂起 → 用户回应 → 工具拿到回应继续。
  差别只有两点：问题谁写的、回答之后做什么。
- 断点只存“这一轮已经发生过的消息”，不存 system 和更早历史；续跑时把
  “用户确认 + 执行结果”伪装成那次工具调用的返回，模型始终站在同一条线上。
- 终态从续体返回判，不从用户那句话猜；取消一次确认和跳过一次提问是两种收尾，
  后者不续跑。
- 工具行原来是前端画出来的，刷新就没了；补进存证之后，实时和回放才一致。
- 位置：1026–1094。

### 主线三：真源只有一个，其余必须可重建

- 数据源是 SQLite 单文件；软删用视图 + `INSTEAD OF` 触发器隔离；审计进
  `_gx_audit`，和业务写入同一个事务；快照是破坏性操作前的退路。
- RAG 里切片原文和向量在 SQLite（唯一真源），FAISS 只是内存派生索引，
  数据一变就失效、下一次检索前重建。跨存储没有事务，所以真源只能有一个。
- 文档也软删：进回收站，检索和列表立即过滤，保留期到了才物理删切片和原文件。
- 产物默认不进语料；用户明确说“收进文档库”时才复制一份，原文件仍留在产物栏。
- 位置：981、999、1070、1120–1134。

## 1. 方法论：怎么做事

### 设计与重构

- **完全解构 ≠ 推倒重写**（902）：解构的是设计，存量里的手写 Loop、薄工具厚服务是资产。
- **设计期间不动代码**（904）：开了“顺手改一下”的口子，就会滑回边做边长。
- **先做预览页，别直接改项目**（906）：改坏了要回滚，改好了没得对比。
- **“一键搞定”要先数前置条件**（910）：Docker 方案的第一步是让用户装 Docker。
- **架构分层重构**（890）：工具薄、服务厚；`main.py` 行数已过时，别引用数字。
- **归类不是减少数量，是给每类定同一套规矩**（916）：读/写/结构/产出四类。
- **入口不同，执行端不该有第二套**（1094）：页面和对话复用同一个执行端。

### 判断怎么选

- **威胁模型决定架构**（912）：单用户本地场景，威胁是“工具自己写错”，不是“恶意用户绕过权限”。`⚠历史`：PG/RLS 已弃用，故事可讲，别写成现状。
- **“只做 Windows”和“写死 Windows”是两件事**（914）：前者是排期，后者是债务。`⚠历史`：条目里的“三处”已过时（`gui='qt'` 已删除），写前重新数。
- **失败不要写“建议”**（918）：工具报告事实，不替模型想下一步。
- **一致性 > 省事**（920）：确认卡片统一成底部弹窗 + 对话内缩略卡两种固定形态。
- **示例不是文档，是行为**（1150）：工具描述和空态里的例子，模型和用户都会当真。
- **能枚举一张表 ≠ 能按软删表去读它**（1148）：`physical_table()` 的由来。
- **死键的来源不是“忘了删”，是改界面时只搬新、不扫旧**（1152）。
- **配置文件是化石层，判断死活的唯一标准是“谁在读它”**（1106）。
- **必需的文件才需要模板，模板本身是个税**（1108）。
- **“想记录”和“该留在代码里”是两件事**（985）：要留的是判断，不是尸体。
- **“没人会用” ≠ “没人会看”**（983）：不会有人 clone 下来跑，但会有人看 README 和设计文档。
- **没有主线，功能再多也模糊**（965）：能跑、评测满分，仍然可能“感觉不对”。

## 2. 排查：怎么找到的

### 值得单独展开

- **视图隔离的三次反噬**：写操作 `affected` 恒为 0（1032，已修）→ 底表默认值被吞（955，已修）→ `describe()` 旧签名在冷路径炸（1036，已修）。同一个教训：每一层抽象都会遮住下一层的某个特性，而且不报错。
- **“健康检查 200” ≠ “代码是新的”**（926）：判断代码真生效只认 `worker 启动时间 > 代码文件修改时间`；排查进程要看全树。
- **“说不出哪里不对”是最值钱的线索**（938）：两次都追到了变量——一次是色温，一次是光效过载。
- **“到处都在” ≠ “用了很多次”，而是“抄了很多份”**（936）：改主色时 `grep` 十六进制色值，才看清三套独立硬编码。
- **裸表拖垮启动**（1148，已修）：`cleanup()` 对每张表查 `xxx_all`；无主键裸表不会被 `repair()` 补保护，启动清理抛 `no such table`，整个应用起不来。

### 其他条目

- **Markdown 中文标点让 `**粗体**` 失效**（924）：CommonMark 的 flanking 规则为英文设计；先用 marked vs markdown-it 对照实验排除实现问题。
- **`trace.tools` 用 `[-1]`**（930）：pending 轮次没有 `add_assistant`，会拿到上一轮；记录调用前长度，只看新增。
- **会话内存缓存覆盖磁盘修改**（934）：`_sessions` 缓存着已加载会话，直接改磁盘会被下次 `save()` 覆盖。
- **成败靠“猜”**（940，已修）：`"error" not in data` 会把 `not_found` 判成功；统一读 `ok`。
- **动作记忆的三个 bug**（942）：只记调过哪些工具、存 8000 字截断、参数按位置切前 3 个。
- **中断的那一轮没进历史**（947）：写操作走不到“最终回答”，模型回看时那一轮是空白。
- **压缩检查放在循环外**（949）：单轮巨任务绕过压缩；安全检查放在循环外，等于对最长的一轮不设防。
- **`dispatch` 无参数防御**（951，已修）：多传、少传、类型错都击穿整轮。
- **熔断按 (工具 + 参数) 计数**（953）：按工具名计会把“换参数探索”误杀。
- **快照清理写了但从来没被调用**（1076，已修）：功能在、注释在、测试过，生产路径一次没接。
- **用户的问题发了两遍**（1034，已修）：`api.chat` 和 `run_agent` 各 `append` 了一次。
- **一行日志把一整轮打翻**（1104）：Windows 控制台 GBK 编不出 emoji/生僻字，`print` 抛 `UnicodeEncodeError` 冒到兜底 except。
- **评测的顺序依赖藏在启动副作用里**（1142）：前面用例起过 uvicorn，lifespan 把真实 LLM 塞进 `api._state`，后面的扫描件用例就“有视觉能力”了。
- **review 抓到的 bug，评测往往抓不到**（1144）：评测验证行为，review 验证组合。
- **状态筛选歧义**（932）：`⚠夹具`，例子是软著表的 `status_raw`，写之前换掉。

## 3. Agent 循环与工具

- **工具薄、服务厚**（890）：工具是菜单 + 传话筒，业务逻辑在 services。
- **给数据，别给结论**（1005）：`query_database` 返回 columns + rows + status，模型自己决定怎么用。`⚠夹具`：例子里的“王五负责的项目”要换掉。
- **`error_type` 是工具返回的一部分，不是异常**（1054）：安全拒绝和参数错误都返回结构化的 `ok:false`，别击穿整轮。
- **SQL 层不该偷偷自修正**（1056）：工具内部修 SQL，模型永远不知道刚才错在哪。
- **“成败”要有个明确的字段**（1058）：判定字段和实际返回对不上，比没有判定更糟。
- **能力清单：一处来源，处处遵守**（1001）：预设打底、卡片覆盖、保守默认；`reasoning_echo`、`context_window` 都从这里读。
- **“填了才带”是碰运气，“认才带”才是规则**（1060）。
- **压缩阈值不该是常数**（1062）：`context_window × compact_ratio`，换模型自动适配。
- **合并两个工具时，参数形状也要合并**（1044）：单条也传数组，一个工具只有一种形状。
- **工具按性质分四类**（916）：读 / 写 / 结构 / 产出，同类守同一个规矩。
- **思维熔断**（1017）：不是压制怀疑，是给怀疑一个出口和终点。
- **异常熔断实测**（1019）：prompt 引导先于程序熔断生效，两层是“第一层先拦，第二层兜底”。
- **A2 分叉管理**（1021）：两种合理解读都展示，比触发澄清省一轮。
- **思考链的语言控制**（1023）：加一句“思考也必须用中文”，中文占比 12% → 62–71%；加强措辞没有正收益。
- **无效旋钮**（971）：`tool_result_limit` 只截“推给界面”的副本，模型吃全量。`已修`：参数改名为“工具返回展示上限”，说明写明只影响界面，不再冒充控制模型 token。

## 4. 中断、确认与历史

- **`ask_user` 不是新机制，是确认卡片的泛化**（1026）。
- **确认卡片本来就在这条路上，只是断头了**（1028）：拿到回答后自己执行、直接给用户一句话，没有把结果还给模型。
- **断点存“这一轮已经发生过的消息”**（1030）：`assistant(tool_calls)` + 已完成的 `tool` 结果 + 挂起调用本身；同一批里排在后面的要显式补“未执行”。
- **续跑的正解：把“用户确认 + 执行结果”伪装成那次工具调用的返回**（993）。
- **终态从工具的续体返回判，不从用户那句话猜**（1084）：导入的取消可能是模型解析出来的。
- **取消一次确认和跳过一次提问，不是同一种收尾**（1090）：后者不续跑，落盘标 `gx_notice`。
- **一轮里可以中断多次，所以卡片是列表，不是字段**（1082）。
- **存证挂在哪条消息上，取决于“什么时候读得到”**（1080）：挂在本轮开头的 user 上，避免续跑途中再中断时的空窗。
- **“已解决”的卡片刷新后就没了**（1040，已修）：问题由 1080 的挂载位置解决。
- **工具行是前端画出来的，历史里没有**（1092，已修）：续跑时用断点的 `call/args` + 续体结果补一条。
- **未解决的中断占输入区的位置**（1038）：底部弹窗占 composer，已解决在对话流里留一行缩略。
- **多问题的答案必须带着问题回去**（1102）：`{question, answer}`，不靠位置对齐。
- **“可点开回看”决定了要不要存详情**（1086）：有展开动作的字段才存。
- **记忆和存证是两件事**（987）：记忆给模型，要精炼；存证给人，要完整。
- **别把对话压成散文**（989）：从对话里留下事实，不是揉成一团话。
- **动作凭据只浓缩、不删除**（991）：删了，模型会谎称自己没做过。
- **压缩不该删消息，只该推进一个指针**（1046）：`summary_upto` 之前的被摘要覆盖，`messages` 只增不减。
- **摘要的输入里必须带动作凭据**（1048）。
- **回放要看的不是 raw，是四个字段**（1050）：`gist / sql / file_path / preview`。
- **“结束了”和“记得结束了”是两件事**（1052）：所有退出路径收进 `_end()`，超时/熔断也要回写。
- **同一句话在一个头里出现两次**（1088，已修）：标题只说状态，scope 交给标签。

## 5. 数据、安全与审计

- **闸门的表名白名单，防的不是“写错”**（1064）：防的是绕过视图直接打底表 `orders_all`。
- **“解析不了”不等于“不安全”**（1066）：解析失败时看关键字，判据贴着意图，不贴着工具能力。
- **特权旁路要有名有姓**（1068）：`system=True` 是一句明确的话，只跳过表名和系统列，语句类型照查。
- **系统表不进白名单，是对的**（1072）：模型本来就不该看见审计表。
- **审计必须和“改库”在同一个事务里**（999、1070）：改成功但审计失败 = 没账；审计写了但库没改 = 假账。
- **保留期是两种东西，不是一个数字**（1078）：软删行 7 天、快照 30 天，重量不一样。
- **视图隔离会吞掉底表默认值**（955，已修）：触发器显式列列表让 `NEW.col` 是 NULL，`DEFAULT` 永远轮不到。
- **写操作 `affected` 恒为 0**（1032，已修）：视图 + `INSTEAD OF` 触发器，`rowcount` 看不见底表改动；用 `total_changes` 差值。
- **一端声明、两端显示，但只存一份**（1098）：关系只存一个方向，读取时摊成出/入。
- **快照留着，表可能已经删了**（1096）：接口给 `exists`，界面标“表已删除”，回滚会重建。
- **“没有表定义”这句话我说错了**（969）：不是没有，是三份互不知道、没有权威。
- **文档也软删**（1132）。
- **文档操作也进审计**（1134）。

## 7. RAG 与文档

- **RAG 不是工具，是子系统**（1120）：上传/删除/重建是人的动作，工具层只露 `search_documents`。
- **切片是真数据，索引是派生数据**（1122）：写只写 SQLite，FAISS 数据变更后整个重建。
- **文档库用 `_gx_` 前缀**（1124）：它不是数据源，不该出现在数据字典、导出、垃圾桶里。
- **产物默认不进语料，收进去要复制**（1126）：交付物和语料是两个身份。
- **Word 预览不引 mammoth，是一次有意降级**（1128）：丢掉字体字号行距，留下内容结构。
- **权重随包，但不进版本库**（1130）：交付物里必须有，版本库里不必有。
- **扫描件不该由“有没有 OCR 引擎”决定**（1136）：没有文字层 → 页面转 PNG → 当前多模态模型；不认图就在发请求前拦。
- **reranker 的接口要有“没有权重”的正确答案**（1140）：不装也能跑，否则它就不是可选的。
- **“没有下载入口”比“给一个下不了的入口”诚实**（1146）：gte 没有公开 ONNX 导出。
- **报告不是“统计功能”，是“排版功能”**（1042）：统计是模型的事，工具只负责把结果画成文档。`⚠夹具`：例子里的软著日期列要换掉。
- **一个词捆着三样东西时，先拆词**（981）：“向量库”= 切片原文 + 向量 + 索引。

## 8. 产品、界面与视觉

- **靠分类，不靠分级**（1003）：设置页按用户会怎么找分组，`normal/advanced` 取消。
- **设置页是给用户的，不是给维护者的索引**（1074）。
- **数值参数的位置，取决于“谁会为它打开设置页”**（1138）：分块/重叠/top_k/门槛放开发者模式。
- **一致性 > 省事**（920）：确认只有两种固定形态。
- **未解决的中断占输入区**（1038）。
- **两种保存节奏可以并存**（1100）：关系立即落库，中文名走草稿；只要界面上分得清。
- **作品集不该抄样式**（1009）：参考对象是终端，项目是 WebUI，评审看的恰恰是设计。
- **图形是名字的证人**（979）：名字靠不住，是因为没有图形能证明它。
- **意象是免检的，事实不是**（908）：“归墟 → 百川 → 航海 → 罗盘”每步都通，合起来跟项目无关。
- **运动 ≠ 发光**（1011）：运动表示“活着”，发光只有报状态时才配存在。
- **雾感 = 把黑提成灰**（1013）：`drop-shadow` 在元素周围铺半透明色，黑不够黑、亮不够亮。
- **质感和光是两件事**（1015）：渐变填充是质感，带模糊半径的才是光。
- **“到处都在”是抄了很多份**（936）。
- **“说不出哪里不对”是最值钱的线索**（938）。
- **示例不是文档，是行为**（1150）。
- **死键**（1152）。
- **“没人会用” ≠ “没人会看”**（983）：README 和设计文档是交付物本身。

## 10. 补充：这轮清理/打包确定的八条

- **产品只有中文，不预支多语言层**：`i18n.js` 改名 `strings.js`，删掉 `en` 和语言切换；
  文案表只留界面真正用到的键。判断是：**没有第二种语言的需求时，多语言框架不是“预留”，是负债。**
  清理死键的过程见 1152；这里补的是“为什么不做多语言”，不是重复那条。
- **设计说去掉 Playwright，代码里还在用**（1154）：PDF 改用系统 Edge 无头模式，Playwright 退出运行时依赖。
  踩到的坑是 Edge 启动器先返回 0、渲染进程异步写文件——**进程返回 0 不等于文件写完了**。
- **项目根是混用的**（1156）：打包后拆成 `RESOURCE_ROOT`（只读）和 `DATA_ROOT`（可写），
  后者落 `%LOCALAPPDATA%\GuiXu`；SQLite 不会替你建 `data\` 目录。
- **首次启动是一条链**（1158）：迁移、写入路径、完成判据三处任何一处停在旧模型，都会导致失败。
- **桌面宿主关掉了自动播放限制**（1160）：`?desktop=1` 直接起播，浏览器仍保留手势闸门。
- **下拉箭头不该抢点击**（1162）：装饰性 SVG 加 `pointer-events:none`，点击穿透到 select。
- **检查更新要分谁发起**（1164）：手动按钮才联网，只查版本给下载页，不自动下载/安装。
- **升级不丢数据靠版本号和备份**（1166）：`user_version` 基线、只增不删、迁移前备份、库新拒绝打开。
